# 开发配置与执行规范设计

状态：选定设计，供实现与验收。范围是开发规范、原生 agent 编排和安装隔离；不实现新的 agent 运行平台。

研究依据见 [prompt/context/harness 报告](research-harness.md) 和 [任务图与 skills 报告](research-orchestration.md)。本文将 graph engineering 具体化为开发任务依赖图；设计选择是针对本仓库的工程判断，来源没有证明本项目已获得质量或速度提升。

## 选定架构

采用「短常驻规范 + 六个职责明确的原生角色 + 两个按需技能 + 独立开发配置目录」。保留现有 Markdown 模板作为内容源，安装时生成 Codex TOML。主 agent 使用 CLI 已有的启动、等待和消息工具执行依赖图；计划记录可恢复的工作契约，运行工具和当前仓库提供真实状态。

| 边界 | 所有内容及责任 |
| --- | --- |
| `templates/AGENTS.md` | 质量不变量、语言、短路由、完整验收原则；不承载长流程或固定流水线 |
| `templates/agents/*.md` | `arch/dev/review/research/refine/plan` 的触发条件、职责边界、输出契约；Claude Markdown 是唯一角色文案来源 |
| `templates/skills/orchestrate/` | 计划定稿后的任务依赖、所有权、并行派发、集成、失败与恢复；参考文件保存计划格式及例子 |
| `templates/skills/author-skills/` | 技能触发描述、按需加载、必要资源与效果验证方法；供编写和修改技能时使用 |
| `scripts/install.ts` | 用 Bun 和内置 API 解析受控模板、生成双端产物及两个 wrapper、备份变更、迁移可确认的旧安装 |
| `scripts/legacy-files.json` | 固定、可审计的旧发布路径与 SHA-256；注明历史版本和源文件，安装时不要求 Git 历史或网络 |
| `install.sh` | 定位仓库并 `exec bun`，保留现有安装入口 |
| `docs/`、`tests/` | 研究证据、设计与效果评估；安装/迁移和真实 CLI 加载验证 |

删除 `templates/codex-agents/` 中重复的六份文案。无需模板引擎、通用 YAML 解析器、插件框架、外部调度服务或新增第三方依赖。

安装器采用 Bun + TypeScript，落实运行时偏好；保留既有 `./install.sh [--home DIR]` 接口和迁移语义。纯 shell 对受控元数据解析、TOML 生成和历史指纹分类增加转义及外部命令成本；Python 原实现可行，但没有必须保留的运行时能力。现有 Python 标准库测试继续作为独立行为及 TOML 解析验证，运行安装器不需要 Python。Bun 不承担 agent 调度，原生 harness 的选择单独评估。

## 备选与否决条件

1. **独立配置目录与两个薄 wrapper：选用。** 如果需求是完整继承个人默认 MCP、登录和历史，仅切换指令，它会成为最差选择；本次明确选择配置隔离，因此首次使用开发配置可能需要单独登录或配置服务。用户可在开发配置中自行设置原生选项。
2. **命令行 profile / 每次临时注入指令。** 一旦必须隔离用户级指令、角色、技能和会话状态，就无法可靠满足要求；Codex profile 不等于独立 `CODEX_HOME`，双端接口也不一致。
3. **自建 DAG 执行器或第三方 agent graph 框架。** 一旦原生工具已经足够运行有界任务，其进程管理、状态数据库和适配层就成为额外故障面。本次只定义可验证的调度契约，复用原生工具。
4. **Claude 原生 Workflows：按任务与实际能力选用。** 稳定的重复流程可以用官方 JavaScript runtime；其逐项 pipeline 支持独立分支推进。主协调者通过原生 `workflow-authoring` 确认当下 API、角色加载与继承规则，不根据版本号推定启用。当前没有具体流程必须生成脚本，也没有本 provider 的实际执行证据，故默认 subagents，并在 `orchestrate` 提供条件选择规则；不发布未经验证的脚本。[官方 Workflows](https://code.claude.com/docs/en/workflows)
5. **Bun 外层调用 SDK/CLI：有明确缺口再增加。** 若需要跨 Claude/Codex 调度或外部进程管理，优先使用 TypeScript + Bun 的小程序调用原生 harness。当前无须额外适配器；Bun 安装器不承担 agent 执行或状态管理。

## 配置和安装接口

`./install.sh [--home DIR]` 将开发内容发布到以下路径，不依赖运行安装器时的工作目录。省略 `--home` 时使用当前用户主目录；指定时只改变安装目标根，不修改进程 `HOME`，便于临时目录验证。除此之外不新增 prefix、profile 或选择性安装选项：

```text
~/.claude-dev/CLAUDE.md
~/.claude-dev/agents/{arch,dev,review,research,refine,plan}.md
~/.claude-dev/skills/{orchestrate,author-skills}/...
~/.codex-dev/AGENTS.md
~/.codex-dev/agents/{arch,dev,review,research,refine,plan}.toml
~/.codex-dev/skills/{orchestrate,author-skills}/...
~/.local/bin/claude-dev
~/.local/bin/codex-dev
```

`claude-dev "$@"` 设置 `CLAUDE_CONFIG_DIR` 为安装时确定的 `.claude-dev` 绝对目录后 `exec claude "$@"`；`codex-dev "$@"` 对应设置 `CODEX_HOME` 后 `exec codex "$@"`。路径以正确 shell quoting 写入 wrapper，运行时不重写 `HOME`。wrapper 保留当前目录、参数边界、退出码和信号行为，不改变原生命令的路径。安装结束提示确保安装目标的 `.local/bin` 在 `PATH`，不修改 shell 配置。

`claude-dev` 另有固定锚点：会话以 `--permission-mode bypassPermissions --effort max --autocompact 900k` 启动；把 `--model` 的值（接受 `--model X` 与 `--model=X`，`--` 之后不再解析）写入 `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` 和 `CLAUDE_CODE_SUBAGENT_MODEL`，没有 `--model` 时不设这些变量。这些都写在 `"$@"` 前面，用户自己写的同名参数仍然生效。后者是因为会话即使只指定一个模型，仍会按原生别名解析内建 subagent 和 auto mode 分类器的模型；别名会变成 Anthropic 模型 id，只服务自有模型名的端点会拒绝，客户端随后报分类器不可用或先等待再回退。`codex-dev` 不设置这些。

隔离承诺只覆盖本项目发布的用户级内容：不写入原生默认目录的新指令或技能，不复制/链接默认认证、settings、config、历史。原生 CLI 仍可读取项目规则、项目配置、环境变量和其本身共享的技能路径；开发模式不是无外部影响的沙箱。用户已经自定义的普通 `claude` / `codex` 保留原本行为。

Codex 角色直接生成 `name`、`description`、`developer_instructions`，不额外创建 `config.toml` 注册；[当前官方接口支持独立 agent TOML 文件](https://learn.chatgpt.com/docs/agent-configuration/subagents)。模板 frontmatter 限定为项目实际使用的简单字段，解析器拒绝重复、缺失和不支持的格式；正文原样作为角色指令，不实现通用 YAML。双端继承父会话模型/推理设置，删除无差别的 `effort: max`。

截至本次本机验证，Codex 0.154.0 在独立 `CODEX_HOME` 下发现 `AGENTS.md`、独立 agent TOML 和 `skills/*/SKILL.md`；Claude 2.1.268 的隔离配置也发现根指令、角色和技能。验证使用真实 CLI 与本地模拟模型端点，不需要云模型调用。最终验收须在新安装产物上重跑，不能把文档格式有效当作 CLI 已加载。

安装先完整解析、生成内容并预检目标类型，再做写入。内容相同则不改动也不产生备份；内容不同先保存原文件再替换；保留开发目录中无关的用户配置。备份用唯一目录并保留原路径，输出可恢复位置。不得跟随待替换文件的符号链接写入目标；拒绝把开发根目录或其受管子目录链接到默认配置等外部目录。使用临时文件加原子替换防止单个文件截断；不实现跨两个配置目录的事务系统。

### 旧安装迁移

默认安装顺带迁移已确认由本项目发布到 `~/.claude` / `~/.codex` 的文件，否则普通命令仍会加载旧规范。所有旧路径必须从历史 `install.sh` 的实际发布行为推导，不能仅根据历史仓库里存在同名文件认定曾安装。

- 在写入前读取并分类所有候选路径。文件内容与固定历史 SHA-256 匹配才可自动迁移；将文件移至备份目录，保留原始字节。
- 旧 `~/.codex/AGENTS.md` 符号链接还需匹配历史目标；旧 `CLAUDE.md` 的 `@AGENTS.md` 转发必须与已确认的被引用模板关联，不能把通用转发文本本身当作所有权证明。
- 用户改写、未知内容、未知符号链接或目录均保留，打印具体路径和未完成的迁移项；不要声称普通配置已完全清理，也不猜测恢复哪个历史 `.bak.*`。
- 只迁移这些文件，不清空原生目录，不修改认证/config/settings，不删除旧备份。新鲜安装不触碰默认目录；第二次安装不重复迁移或备份。
- 安装器依靠随仓库发布的指纹数据工作；归档下载与浅克隆同样可安装。历史指纹的生成来源及覆盖范围须在测试或注释中可追溯。

## 内容和执行契约

常驻规则保留八类：读真实代码和约束；解决完整目标；最少必要抽象与依赖；校验信任边界；意外失败保留原因并暴露；改动可追溯且不撤销他人工作；验证真实行为且标明未验证部分；按任务独立性与实际收益委派。允许有明确恢复语义的错误处理，不能把「少校验、少 catch」误写成删除输入校验或必要清理。先复现、再修复，检查应覆盖真实用户路径。

删除固定次数重启、无证据归因于上下文、所有任务强制完整角色流水线、必选方案数量、强制风格挑刺，以及「每个 loop 都是新上下文」等未经接口保证的说法。出现重复失败且无新证据时重新诊断并改变策略；是否交接、压缩或重开会话由真实问题决定。

主 agent 决定任务路由和派发；角色不再自行递归扩大工作树。简单任务本地完成；独立领域研究可并行，接口和所有权确定后再并行开发。架构设计指出依赖与集成检查，计划把它们变成明确任务。review 只读，优先报告有具体失败条件的正确性、回归、复杂度和验证缺口。

`orchestrate/references/plan-format.md` 是计划格式的唯一规范；主 agent 调用 `plan` 时传入该契约，plan 角色不另抄一套 schema。计划使用一份 `plan.md`，包含 Goal、Constraints、Done when、Tasks 和运行记录。每个任务具有以下字段：

| 字段 | 契约 |
| --- | --- |
| `id` / `role` / task text | 唯一稳定标识、执行角色和有界行动；不得暗含尚未决定的架构 |
| `deps` | 已存在的任务 ID，图无环；消费者依赖生产者，包括读取另一任务正在修改的接口 |
| `owns` | 明确可写文件或目录；只读任务为空；共享文件必须归属一个任务或加顺序依赖 |
| `acceptance` | 可观察产物及验证命令/检查方法，不能只写 agent 自报完成 |
| `state` | `pending`、`running`、`blocked`、`done` |
| 运行记录 | 派发后记录真实 agent/session 句柄、工作区或 worktree；结束记录修改范围、命令及结果、证据所对应的 revision 或文件状态 |

调度不变量：

1. 派发前校验任务 ID、依赖、环路、写入范围及验收条件。`ready` 是依赖全部 `done` 的 `pending` 任务，再排除与正在运行任务冲突的写入及共享资源；按当前工具并发额度一次派发可并行集合。任一任务集成验收后立即重算，不等待无关慢任务组成的整批屏障。
2. 每个 worker 收到目标、约束、所有权、已定接口、验收条件和返回格式；明确其他 worker 同时存在、不得撤销他人修改。workers 不修改共享计划，不合并其他工作区。
3. 一个协调者写计划、分配任务和集成结果。无冲突的小任务可共享工作区；需要分支隔离时采用工具原生 worktree 能力，不假定并行本身提供文件隔离。合并必须串行。
4. `done` 只表示产物已经集成到后继实际消费的位置并通过验收。worker 完成消息或分支上的测试通过不能直接解锁后继。最终集成检查在所有相关任务之后执行。
5. 恢复时读计划，再检查当前 Git/文件状态和真实工具句柄。超时不是终止；有活句柄先观察或接管，只有确认终态或句柄不存在才考虑重新派发，避免双写。
6. 失败只阻塞后继；继续独立分支。重新派发必须带新诊断或变化后的前提。依赖、接口或目标改变时更新受影响任务，原有证据过期则重新验收。没有就绪任务时，有真实活句柄则等待，否则调查阻塞或计划错误，不能把无任务可派发当作完成。
7. 所有 Done when 都有当前证据才结束。`plan.md` 是协调记录，不能代替仓库、运行进程和验证结果成为唯一事实来源。

`author-skills` 将技能编写实践落地：描述同时写清正向触发和不适用情况；SKILL.md 只放必要步骤，长规范与例子放有明确链接的参考文件；只有重复且确定性的操作才增加脚本；不放常识性长文、相互矛盾的强制规则或无法兑现的权限能力。验证涵盖应触发、相邻任务不应触发、异常和真实产物检查，不以关键词出现等同效果。

## 实施顺序与所有权

| 顺序 | 所有者 | 文件及完成条件 |
| --- | --- | --- |
| 1 | root / plan | 依据本设计写本次 `plan.md`，固定安装与内容接口，任务含依赖、所有权、验收 |
| 2A，可与 2B 并行 | installer dev | `install.sh`、`scripts/install.ts`、`scripts/legacy-files.json`、`tests/test_install.py`；覆盖新装、升级、幂等、路径/符号链接、迁移与 wrapper 行为 |
| 2B，可与 2A 并行 | content dev | `templates/AGENTS.md`、`templates/agents/*.md`、两个 skills、删除 `templates/codex-agents/`、`tests/test_contracts.py`；单源角色、明确 DAG 和技能契约，静态检查只证明格式/一致性 |
| 3 | root | README、研究汇总及评估记录、`tests/test_cli.py`；在完整安装产物上验证两端真实加载和普通配置不受新增污染 |
| 4 | review → 对应 dev → root | 只读评审、修复、重跑有变化的验证、逐条核对 Done when；后续任务仅在集成验收后解锁 |

本设计文件由 architecture 负责；两个 research agent 各自负责研究报告。实现人员不得回滚他人工作。安装器不依赖旧 Codex 模板存在，内容实现不修改安装逻辑，使 2A/2B 可独立推进。

## 验收与边界

- 新鲜临时 HOME 安装成功，所有预期指令、六个角色、两个技能生成；默认配置内容保持逐字节不变。真实 Claude/Codex 加载证据覆盖 root、roles 和 skills，解析成功只是前置检查。
- wrapper 在含空格路径和含空格/特殊字符参数时保持 argv、cwd、对应配置根及退出码；缺失原生命令时清楚失败。无条件覆盖已有配置根环境变量，才能保证 dev 命令进入固定开发配置。
- 重复安装无内容变化、无额外备份；变更安装能恢复旧产物；无关开发配置不变；不得通过符号链接改写默认目录。
- 旧历史样本自动备份移出加载路径，未知自定义样本保留并报告；转发和符号链接关联规则有独立案例，归档场景不依赖 Git。
- 角色语义来自同一源，生成 TOML 可用真实解析器解析且指令正文一致；源模板和技能格式失败时在写入前暴露。
- 执行契约用 fork/join、共享写冲突、失败独立分支继续、陈旧 running 状态、集成后解锁这些场景检查；至少一个有界原生多 agent 实际运行验证并行派发与最终集成。仅文字断言不能证明运行效果。
- 效果评估采用固定任务快照、模型和预算，覆盖小 bug、错误抽象、边界校验、异常暴露、真实用户路径、并行集成、恢复和缺失验收证据；记录行为验收、盲评结论、耗时/用量/返工。若未完成有统计意义的新旧多次对照，不声称已证明开发质量或速度全面提升。
- README 明确登录与个人服务配置独立、项目配置仍生效、支持且实际测试的 CLI 版本、升级/迁移与备份恢复办法。最终逐条报告已验证和未验证范围。

本次不承诺任意项目都能达到“极致”质量，不更改 CLI 权限默认，不继承个人认证，不固定模型/并发数，不实现自动发布、进程常驻、任务数据库或跨进程无人值守调度服务。未来只有真实效果评估暴露缺口时再增加机制。
