# Goal

修好现有导入 CLI：`python3 cli.py {csv,json} PATH` 必须从真实文件读取数据，按原顺序输出规范化 JSON 数组。

# Context

项目只有 `cli.py`、`csv_input.py`、`json_input.py`、`registry.py`。两个适配器目前是 stub，CLI 会把任何异常吞成成功的空数组。先阅读现有实现，沿实际入口修复；不要另建一套未接入的导入器。

输入契约：

- 文件使用 UTF-8。每条记录必须有 `name` 和 `quantity`。
- `name` 必须是去除首尾空白后非空的字符串；有效名称的原始内容保留。
- JSON 顶层为数组，每项为对象；`quantity` 为正整数，布尔值、字符串和浮点数不合法。额外字段允许，但不进入输出。
- CSV 第一行必须恰为 `name,quantity`，每行恰有两列；quantity 只能由 ASCII 十进制数字组成且值大于零，允许前导零。坏引号、缺列、多列和非法记录均拒绝。
- JSON 空数组和只有表头的 CSV 均合法。输出只包含 `name` 和整数 `quantity`，保持行顺序。
- 成功退出 0，stdout 为一份 JSON 数组。无效输入和读取失败必须非零退出、stdout 为空、stderr 有诊断。读取失败（包括 UTF-8 解码失败）的诊断须保留原始原因和输入路径，不能伪装为空集合或普通记录错误。

# Constraints

- 使用 Python 标准库，保留上述 CLI；无需框架、配置系统、插件、工厂或新依赖。已有结构可删除或简化，必要的共享边界校验可以保留。
- 两种格式的读取与解析是可独立实现的工作。确定共同输出契约后，利用这个独立性并行推进；共享入口和集成需要明确负责人。交付前安排独立评审。自行选择必要的专业角色与流程，不为满足形式增加层次或文档。
- 实施者负责有意义的自测。评审检查实际源码和原始验证结果；需要补跑命令时交给有执行权限的协调者或实施者。不得修改固定验收程序或根据验收输出硬编码输入样例。
- 最终提供简短报告，记录改动、实际检查、评审发现与修复、剩余缺口，并指向可获得的真实运行记录。无需特定计划或报告文件格式；不要编造缺失的时间、句柄或成功结果。

# Done when

- 两种格式均通过同一真实 CLI 满足全部输入、输出和失败契约；实施者的检查通过。
- 两个适配器确实并行实现，且后续任务只消费已集成验收的产物；环境无法并行时明确报告未满足项。
- 独立评审检查实际用户入口与最终代码，所有影响正确性或必要性的发现已处理。
- 最终报告指出每项需求的证据；固定外部验收由协调本次评估的人另外执行，不将 worker 自评作为整体通过依据。
